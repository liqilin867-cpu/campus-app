# 校园事务工作台 UI 重设计方案

## 目标

将当前 App 重新设计为统一、清晰、移动端优先的「校园事务工作台」。新版应像一个真实日常使用的校园工具，重点服务缴费、宿舍分摊、账单、消息和校园生活服务，同时保留现有业务流程。

## 范围

本次是全 App 视觉统一改版，覆盖：

- 登录与注册
- 首页
- 服务页
- 账单页
- 消息页
- 我的页面
- 分摊缴费页面
- 夜间保电页面
- 通用弹窗、底部导航、按钮、卡片、输入框、空状态

本次不改变登录、充值、缴费、分摊、消息、localStorage 保存和服务端持久化逻辑。

## 设计方向

采用「校园事务工作台」方向：

- 清爽、克制、耐看，适合每天反复使用。
- 减少蓝紫玻璃拟态、大面积渐变和装饰光斑。
- 强化信息层级，让待缴、余额、分摊、消息状态一眼可见。
- 以可信的校园蓝/墨蓝为主色，用语义色表达状态。

## 视觉规范

### 色彩

- 背景：浅灰白工作台底色。
- 主色：深校园蓝/墨蓝，用于主按钮、导航选中和关键标题。
- 成功：绿色，用于已缴、已批准、完成、安全状态。
- 警示：橙色，用于待缴、提醒、分摊追踪。
- 功能色：青色/蓝绿色，用于水费、用能等辅助信息。
- 危险：红色，用于删除、重置、错误和高风险操作。
- 深色模式：低饱和深灰蓝背景，并保留同一套语义色。

### 形状与层级

- 卡片统一使用 8-12px 圆角。
- 减少毛玻璃、霓虹阴影和大面积渐变。
- 优先使用清晰边框、轻阴影和稳定间距。
- 避免卡片套卡片；卡片主要用于真实内容项、弹窗和重复列表。

### 字体与排版

- 金额、待缴数量、状态数字要突出。
- 辅助说明文案更短、更轻。
- 按钮文字控制长度，避免移动端挤压。
- 不使用随视口变化的字体大小。

### 通用组件

- 底部导航保留：首页 / 服务 / 账单 / 消息 / 我的。
- 选中态更稳重，不使用过重气泡渐变。
- 按钮按语义统一颜色：主操作蓝色，成功绿色，提醒橙色，危险红色。
- 弹窗统一标题、关闭按钮、主次按钮和内容间距。
- 图标继续使用 lucide-react。
- 输入框、筛选 chips、徽标和列表行统一边框、圆角和间距。

## 页面设计

### 登录页

保留学号密码、短信登录、注册、第三方绑定和演示账号逻辑。视觉上改为更安静的校园认证入口：减少装饰光斑，使用紧凑身份卡片，统一 tabs、验证码、协议和快捷登录按钮。

### 首页

首页改成核心仪表盘：顶部显示宿舍、当前用户和通知入口；主卡突出校园卡余额；水、电、网用紧凑指标卡展示；充值、分摊、一键缴费作为清楚的快捷操作；待缴/分摊追踪提前展示；用能走势保留但降低视觉噪音。

### 服务页

服务页改成分类清楚的工具区：常用服务使用 2x2 网格，更多服务用列表或双列卡片。搜索保留但不抢主视觉。订餐、洗衣、报修、活动、跳蚤市场、失物招领弹窗统一成同一种弹窗/抽屉语言。

### 账单页

账单页强化「财务记录」感：顶部显示累计消费、已缴、待缴；有待缴时突出分摊追踪；账单按月份分组，行内展示图标、项目、时间、金额和状态；账单详情像电子凭证，但减少装饰，突出金额、项目、单号、支付方式和状态。CSV 导出保留。

### 消息页

消息页改成收件箱体验：保留分类筛选；未读状态明显但不吵；删除按钮弱化；空状态简洁统一。

### 我的页面

我的页改成账户中心：头像、宿舍、室友、钱包、安全设置、保电申请、主题切换、反馈、修改密码、关于、重置和退出登录分组展示。减少拟物阴影，统一列表行样式。

### 分摊缴费页

分摊页保持任务式流程：顶部返回和金额摘要清晰；账单选择、分摊方式、室友分配和确认提交分成明确步骤；比例模式保留总和校验；提交按钮文字缩短，适配移动端。

### 夜间保电页

保电页使用同一套工作台样式：当前状态卡、时间选择表单、提交状态和历史记录统一排版。

## 数据与行为

实现时保留：

- 现有 React state 和 props 关系。
- 登录成功、退出登录逻辑。
- localStorage 数据结构。
- 现有通知和 toast。
- 充值、一键缴费、分摊、室友代付、服务购买、报修、活动报名、保电申请等流程。

如果乱码只出现在终端读取结果里，不纳入本次 UI 改版；如果浏览器页面实际显示乱码，应作为单独的可见文本问题处理。

## 验证方式

实现后需要：

- 运行 TypeScript 检查。
- 运行生产构建。
- 如果能启动本地服务，提供访问地址。
- 检查移动端宽度下文字不溢出、底栏不遮挡、弹窗适配、深色模式对比度正常。
- 验证关键流程：登录、充值弹窗、分摊、账单详情、消息已读/删除、服务弹窗、主题切换、退出登录。

## 不做的事

- 不新增外部 UI 库。
- 不迁移数据模型。
- 不改后端 API。
- 不新增与视觉改版无关的功能。
- 不做无关的大范围重构。

## 当前假设

- App 继续保持移动端优先，页面仍限制在手机宽度体验。
- 继续复用现有 shadcn、lucide、Tailwind 体系。
- 本次按全 App 统一改版执行，而不是只改首页。
